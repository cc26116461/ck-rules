# CK的规矩

把一个文件里的对话规矩，注入到每次会话的系统提示里。附带执行权限档位。

## 它做什么

1. 读取规矩文件（默认 `prompt/default.md`，也可指向你自己的 Markdown）
2. 把其中的 `{{OWNER}}` 换成你配置的名字
3. 在系统提示里挂成一个独立段落，排在 persona 之后、工具说明之前
4. 在末尾追加当前执行权限档位的约定

不修改 DSH 宿主文件，不打补丁，不写会话日志。卸载插件段落即消失。

## 配置

在 `cordis.patch.yml` 的 `config` 里改：

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 关掉整个注入 |
| `ownerName` | 空 | 替换规矩里的 `{{OWNER}}`；空时用「你」 |
| `permissionMode` | standard | `loose` 宽松 / `standard` 标准 / `strict` 严格 |
| `promptFile` | 空 | 规矩文件绝对路径；空时用内置 `prompt/default.md` |
| `order` | 450 | 在系统提示里的排序位置 |

三档权限的差别：

- **宽松**：读写都直接做，不问
- **标准**：只读直接做，写文件、改配置、删除前先问
- **严格**：每步都问

这三档是写给模型的约定，不是操作系统级的沙箱。真正的文件隔离仍由 DSH 自己的文件策略决定。

## 限制

- 注入是全局的：同一 profile 的所有会话都会带上
- 规矩文件读不到时只在日志里警告，不会让会话启动失败
- 与其它注入型插件同时启用会产生两段并存的规矩，需要各自关闭其中一套

## 卸载

在 DSH 的插件列表里关闭或移除 `ck-rules`，系统提示里的段落随即消失。
